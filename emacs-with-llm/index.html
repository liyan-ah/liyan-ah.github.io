配置动机

大模型时代，一切都变化得如此之快。在这样的背景下，在 Emacs 中拥抱大模型也是一种情怀。笔者对大模型的使用有两种模式：chat 模式，一般是一些信息的确认，充当搜索引擎结果的总结和汇总，如确认一些书籍的信息，或者和大模型讨论一些观点；agent 模式，coding 工作或者是要基于已有的一些知识来推进工作，如结合已有的文章来调整新博文的行文思路，确保尽量和此前的博文保持一致。

此前这两种模式均是在外部的网页或者其他编辑器里执行的，一度让笔者的 Emacs 处于空闲状态，日常的工作都不在 Emacs 中进行了。最近痛定思痛，还是好好调研一下，调整现有的 Emacs 配置，引入大模型来进行增强。

融入 Emacs 体系

可以完美的融入已有的 Emacs 体系。首先，可以在 Org 生态中进行扩展，将大模型作为一种语言嵌入到 Org Babel 中。结合快捷键，就可以在 Org 文档撰写的时候插入一段大模型的对话，或者和大模型做一下讨论。

如下是一个调用本地小模型的示例，可以在文档撰写的时候，插入一些调用大模型生成的内容。

北宋和南宋的兵制有一些明显的变化
#+BEGIN_SRC llm :results output raw :model local-low-power
对北宋、南宋的兵制进行一下介绍，并且做下比较
#+END_SRC

#+RESULTS:
#+begin_example
宋朝是中国历史上一个非常重要的时期，对于军事制度和战争策略有着深远的影响。以下是对北宋、南宋两代兵制简要描述及其主要特点及对比分析：

### 北宋

,**兵制概况：**
- 宋初时实行的“五卫精锐”与“九天策御法”的军事体系是其典型特征。
- 以骑兵和步兵为主要作战力量，配之弓箭、长枪等装备。

#### 特点：
1. **战车制度**：宋朝曾有战车使用史迹记载。这是一种结合了轻便战术与机械化战争的尝试。
2. **军事节度使**：军队由地方节度使掌控，并受中央直接指挥，这表明当时已经出现了初步的地方军权。

### 南宋

#### 特点：
1. 由于北方战事频繁导致大量兵员南下。南方气候和地理环境对兵种配置产生影响。
2. **舟船与火器**：水路运输发达以及火炮的广泛使用，是南宋军事策略中的特色。
3. **军队编组变化**：由“厢军”（即府州地方武装）为主向以中央派遣将领为领导机构转变。

### 比较分析：
1. 从整体来看，两代兵制都体现了对步骑并重的重视。但南宋时期的骑兵逐渐退化，而舟船和火器则成为南方军事的主要优势。
2. 南宋时期由于地理环境的影响（尤其是长江三角洲），战场环境发生了较大变化，这使得水上作战方式得到了更广泛的运用与推广。

总的来说，北宋时期的兵制以战车作为亮点之一，并且地方军权有所加强。而南宋的兵制则更加倾向于根据南方气候和地形进行调整，特别强调舟船使用及火器发展的重要性。

通过这种历史分析可以看出，在不同地理环境下的战争环境中产生的军事策略是具有高度灵活性与适应性的特点。
#+end_example

配置思路

首先是模型的部署、选择。笔者采用的是本地小模型+大模型服务商接口两种方式。一般的轻量级任务使用本地的小模型，更加深入的探索则需要使用在线的大模型来处理。本地小模型使用ollama进行部署，选择qwen2.5:1.5b小模型，笔记本运行没有压力。在线模型则是使用deepseek，基本满足日常使用。

其次是如何落到 Emacs 生态中。Emacs 生态下也有一些大模型的扩展，笔者选择的是ellama。使用较为灵活，支持设定不同的provider以定义本地小模型和在线大模型。实际使用时，也可以灵活的选择不同的 provider 来处理对话。

然后是配置的绑定。这一点就要结合个人的使用需求了。比如，下面是笔者的配置，可供参考。

;; evil visual state 下把选区发送给 ellama chat。
(defun my/ellama-ask-selection-operator (beg end)
  "把选区 BEG..END 直接发送给 ellama chat。"
  (ellama-chat (buffer-substring-no-properties beg end)))

(evil-define-operator my/ellama-ask-selection (beg end _type)
  "Evil operator：将当前可视选区发送给 ellama chat。"
  :move-point nil
  (interactive "<R>")
  (my/ellama-ask-selection-operator beg end))

;; C-c C-x a：evil visual state（含 Ctrl-v block 选区）内发送选区，
(define-key evil-visual-state-map (kbd "C-c C-x a") #'my/ellama-ask-selection)

;; 定义一种 llm babel 类型，在 org mode 中可以调用。并且定义一个插入的快捷键。
(defun org-babel-execute:llm (body params)
  "Org Babel llm 代码块执行器。
BODY 是块内提示词文本，PARAMS 可携带 :model 参数。
支持 :model local-low-power / cloud-deepseek，省略则用默认 provider。"
  (let* ((model-arg (cdr (assq :model params)))
         (chosen-provider (my/ellama-resolve-provider model-arg))
         ;; 用 llm-make-chat-prompt 构造合规的 chat-prompt 对象
         ;; 系统约束放入 :context，用户提示词作为 content
         (prompt (llm-make-chat-prompt
                  body
                  :context
                  "You are a rigid LLM backend running inside an Org-mode Babel block.
Process the request directly.
Do not wrap the output in markdown code blocks unless requested.
No conversational filler, no greetings.
Respond in Chinese unless requested otherwise."))
         ;; llm-chat 同步阻塞调用，返回完整字符串
         (response (llm-chat chosen-provider prompt)))
    (if (stringp response)
        (string-trim response)
      "Error: 未能获取到有效的模型回复。")))

(defun my/org-insert-llm-src-block (prompt)
  "在当前行之后插入一个 llm Org Babel block，并写入 PROMPT。
交互调用时从 minibuffer 读取 PROMPT。"
  (interactive (list (read-string "LLM 提示词: ")))
  (unless (derived-mode-p 'org-mode)
    (user-error "该命令只能在 Org mode 中使用"))
  (end-of-line)
  (unless (bolp)
    (insert "\n"))
  (insert "#+BEGIN_SRC llm\n" prompt "\n#+END_SRC\n")
  (forward-line -1)
  (end-of-line))

(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c C-x l") #'my/org-insert-llm-src-block))

;; 使用 ellama-define-word 来进行文本翻译、解释
(global-set-key (kbd "C-x t") 'ellama-define-word)
